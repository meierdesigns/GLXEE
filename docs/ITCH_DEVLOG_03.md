# Devlog #3 — The galaxy fights back

**GLXEE** · meierdesigns · VOLTEX transmission 03

---

GLXEE used to give the pilot a map and ask, “Where do you want to go?”

Now the map has an answer.

Factions expand. Bases hide at the edge of a galaxy. Stations appear along
their preferred frontier. A new pilot begins with an invasion already moving
through the home theater.

The next jump is no longer just travel. It is a decision.

## A living galaxy

Every galaxy has a ruler, a base, and an expansion doctrine:

- Terran outposts stay near the core.
- Kronax war camps push toward the frontier.
- Voidborn sanctums keep their distance.
- Pirate hideouts appear wherever the salvage is good.
- Machine relays spread across the grid.

Travel advances the simulation. Victorious battles advance it too. New holdings
add defenders, change the pressure around a planet, and stock faction stations
with parts from their own doctrine.

The base is deliberately hard to find. When all stations around it are raided,
the base becomes exposed. Break the base and a held galaxy becomes contested.

That gives a galaxy a shape beyond its background color: it has a front line,
an economy, and something worth defending.

## The opening invasion

New profiles now begin with a small crisis close to home.

The scenario seeds a neighboring planet with a hostile faction, unlocks the
route, and makes the attacker visible in combat. Clear a stage there and the
invasion is repelled for a starting reward.

It is a compact tutorial for the larger loop:

```text
read the map → reach the threatened planet → clear the stage
      → earn the reward → see the faction balance change
```

The pilot does not start as a spectator. The first launch already has a reason.

## Combat that hands back to the station

The combat pass focused on the space between “stage cleared” and “back at the
station.”

Enemy lanes, wave staging, obstacle patterns, pickups, and victory loot now
share a clearer handoff. Mission rewards are paid at the right moment, victory
notices explain what changed, and the next station decision is easier to read.

The result is a more deliberate rhythm:

```text
approach → survive the pattern → defeat the champion → claim the field
       → resolve mission / invasion / raid → return to the station
```

The shooter is still fast. The consequences are simply less easy to miss.

## Hangar engineering

The hangar is becoming a workshop instead of a preview screen.

Weapon slots can be purchased, sized, and mounted on the nose, core, or wings.
Drag placement is bounded so hull areas do not overlap and weapon sockets do
not stack on top of each other by accident. Power budget, part fit, and slot
size are visible while the loadout is being built.

The useful question is no longer only “Which weapon is strongest?”

It is also:

- Is this a single centreline mount or a mirrored split mount?
- Does the part fit the slot size?
- Is there enough power for the whole ship?
- Can the wing survive the shape I just designed?

The hangar should make those answers visible before launch.

## A README that speaks the same language

The project guide now uses the same vocabulary as the game: transmission
panels, status readouts, faction theaters, station tabs, and wave history.
Existing pixel assets provide the chapter headers and ship / planet gallery.

It is a small detail, but it matters. GLXEE is a game with a strong shell, and
the documentation should feel like it came from the same archive.

The README style is now also a project rule, so future updates keep the
VOLTEX / Game Boy visual language instead of drifting back into a generic
feature list.

## What is next

The next pass is about making the faction pressure easier to understand in the
station: show holdings, missions, reputation, and trade as one readable command
picture.

The galaxy has started moving.
